# API Automation Framework

Базовый фреймворк для автоматизации тестирования REST API. Построен на паттернах чистой архитектуры и принципе "Convention over Configuration" — минимум хардкода в тестах, максимум гибкости через YAML-конфигурации.

## 🛠 Стек технологий

* **Язык:** Java
* **Сборщик:** Gradle (Kotlin DSL)
* **Фреймворк:** TestNG
* **HTTP-клиент:** RestAssured
* **Ассерты:** AssertJ
* **Работа с данными:** Jackson (DataBind + YAML)
* **Логирование:** SLF4J + Logback
* **Отчеты:** Allure

## 🚀 Основные фичи (Под капотом)

* **Умный биндинг тестовых данных:** Фреймворк сам находит и подтягивает нужный блок данных из папки `test_data/` на основе параметра `testName` в аннотации `@Test`. В тестовом методе достаточно вызвать `testData()`.
* **Изоляция окружения:** Настройки стендов (базовые URL, дефолтные доступы, доступы к БД) вынесены в `envs/stand_data.yml` и легко читаются через метод `env()`.
* **Кастомные ретраи:** Встроенный `RetryAnalyzer` автоматически перезапускает упавшие тесты (количество попыток задается глобально в YAML-конфиге).
* **Централизованное управление:** Фильтрация тестов для запуска и базовые настройки раннера вынесены в единый файл `framework-config.yml`.
* **ApiBaseTest:** Все тесты наследуются от базового класса, который инкапсулирует инициализацию HTTP-клиентов и хелперов данных, оставляя код самих тестов максимально чистым.

## 📂 Структура проекта

```text
src/test/
├── java/
│   ├── Config_lib/    # Парсер главного конфига, Listener'ы, RetryAnalyzer
│   ├── Data_lib/      # Хелперы для работы с YAML (TestDataHelper, EnvDataHelper)
│   ├── Requests_lib/  # Обертки над RestAssured (GetRequest, PostRequest, Builder)
│   └── tests/         # Сами тестовые классы (наследуют ApiBaseTest)
└── resources/
    ├── envs/          # Конфиги окружения стенда (stand_data.yml)
    ├── test_data/     # YAML-файлы с тестовыми данными для конкретных кейсов
    ├── framework-config.yml # Главный конфигуратор запуска
    └── logback.xml    # Настройки вывода логов
```
